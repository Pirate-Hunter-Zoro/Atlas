THE FOUR THINGS TO ACTUALLY GET OUT OF THE CHAT

  1. The password itself, for that key and MathID. This is the whole point.
     Everything else is a fallback.

  2. If they say a site administrator has to do it - get them to say that
     plainly, and ask whether they can escalate it themselves rather than
     handing you back to the university. Then send the email in Part 2.

  3. The exact hostnames and ports Mathematica needs for activation. Ask for
     this even if they solve the problem another way. It is what Laureate IT
     needs in order to whitelist the endpoint, and it fixes this permanently
     for every future machine instead of one node today.

  4. Whether this site license expects a MathLM license server rather than
     per-machine activation keys. If it does, the whole approach changes and
     you need the server hostname from TU - worth ruling out in one question.

LIKELY PUSHBACK AND HOW TO ANSWER

  "Just use automatic activation."
      The node has no DNS resolution for activate.wolfram.com. Not a firewall
      refusal - the name does not resolve at all. register.wolfram.com resolves
      and answers normally, so the block is specific to the activation endpoint.

  "Is this a personal or organization license?"
      Organization. University of Tulsa site license, valid through
      14 October 2026.

  "Are you an administrator on the machine?"
      No. Mathematica is installed under the home directory without root. That
      is supported and is not related to the activation failure - the kernel
      runs and reports its MathID correctly, it just has no password.

  "Try a different activation key."
      Only if they confirm the first one is the problem. Two keys remain on the
      account and a password is bound to one key and MathID pair, so do not
      spend both chasing the same error.

  "Have you tried reinstalling?"
      No, and it would not help. The install is complete and functional.

WHAT NOT TO DO

  Do not read out all five activation keys. One key, the one above.
  Do not accept "contact your site administrator" as the end of the chat
  without also getting item 3 - the hostnames and ports.

WHEN YOU HAVE THE PASSWORD

  Paste it back into this session. It is a long string bound to that key and
  MathID; it is useless on any other machine, so there is nothing to guard
  beyond the key itself. The mathpass file gets written and the kernel verified
  from here.
