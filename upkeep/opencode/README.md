# upkeep/opencode: the OpenCode parity layer

Gives DeepSeek inside OpenCode (1.19.5) the long-running harness tools: wakeups, cron, background shells, monitors, background agents, forks, workflow scripts, worktrees, notifications.

`python3 upkeep/opencode/install.py [--dry-run] [--home DIR]` installs it into `~/.config/opencode`. Exit status is the number of problems. `upkeep.py run` calls it; it is idempotent. Tests: `python3 -m unittest upkeep/opencode/test_install.py upkeep/opencode/test_parity.py` (the second runs the plugin under node with a stub client).

| File | Installed as | Role |
| --- | --- | --- |
| `plugins/parity.ts` | `~/.config/opencode/plugins/` | Every tool, the capabilities prompt and the Playwright browser MCP. It must export only `ParityPlugin`, because OpenCode calls every exported function as a plugin |
| `agents/*.md`, `commands/*.md` | same names | `worker`, `fixer` and `structured` on flash; `deep`, `reviewer` and `verifier` on v4-pro. `reviewer`, `verifier` and `structured` deny edits by permission. `reviewer` and `verifier` share one bash rule set. Its first rule is `"*": deny`, because the last matching rule wins. It allows commands that cannot write or run code whatever their arguments, git's read subcommands without `--output`, and one test file per `python3 -m unittest`. So no `sed`, `rg`, `find`, `sort`, `node` or `git grep`, whose arguments can write or run a program (`-iO` runs one), and no `brew bundle` or `mise`, which evaluate a config as code. OpenCode matches each simple command's text, never an expansion, so the rules refuse `>`, `$` and backticks in it. A redirect on a subshell, group or loop is in no command's text, OpenCode skips `cd`, and it matches quotes literally, so the bash rules narrow the shell but cannot make it read-only. The plugin's read-only rule, which parses the whole line, does: under `--pure` these two agents can write. `/ultracode` runs on v4-pro through `model:`, not `agent:`, because a subagent would run it as a subtask that ends before its workflows report. `/loop`, `/review`, `/simplify` |
| `capabilities.md` | `~/.config/opencode/capabilities.md` | Added to the system prompt by the plugin: the tools, how work is judged, the workflow API and what the user can type. Names tools only, no vendor |
| `config.json` | merged into `opencode.jsonc` | The managed keys. Never copy it into the config dir: OpenCode loads a `config.json` there as config |
| `package.json` | merged into `~/.config/opencode/package.json` | Pins `@opencode-ai/plugin` and `sdk` to the opencode version; bump both with opencode |
| `env` | read by `shell.zsh` | Feature flags. Never `OPENCODE_EXPERIMENTAL=1`: it turns on the unstable code mode |
| `launchd/com.mikeyferguson.opencode-serve.plist` | `~/Library/LaunchAgents/` (by upkeep.py, `@HOME@` filled) | The persistent server on 127.0.0.1:4096. Its env block is `env` plus `PATH` and `PARITY_PRIMARY=1` (a test checks) |
| `shell.zsh` | sourced from the upkeep block in `~/.zprofile` | Exports `env`; `oc` and `ocrun` attach to the server with `--dir "$PWD"`, or run a local opencode when it is down |
| `coder` | `~/bin/coder` | Same attach-or-fallback; keeps the line `exec opencode --auto` the doctor looks for |

The config merge parses JSONC and keeps every unmanaged key. A file that does not parse is reported and left alone. A commented original is saved once as `opencode.jsonc.before-upkeep`, because the rewrite drops comments. The merge deletes the `openrouter`, `groq` and `cloudflare` provider blocks, and drops `plugin` entries for files under `plugin/` or `plugins/`, which load automatically.

Top-level `permission` stays the string `"allow"`, because MO's legacy opencodedoctor resets any other value every minute. `doom_loop` and `external_directory` still default to ask under it, so `agent.{build,plan,general,explore}` and the agent files allow them.

The board's tutor runs `opencode --pure`, which loads no plugins but does read the global config and starts its MCP servers. Everything that only makes sense with the parity tools (the capabilities prompt, the browser MCP) therefore comes from the plugin, not from `opencode.jsonc`. `PARITY_BROWSER_MCP=0` turns the browser MCP off.

Skills under `~/.claude/skills` and `~/.agents/skills` (any directory holding `SKILL.md`) are copied into `~/.config/opencode/skills`. Hidden directories such as `.trash` are skipped, and so is any skill that names a Claude-only surface (`mcp__claude-in-chrome`, the Claude desktop app, Claude's memory). Nothing is ever deleted.

## How the plugin works

- Every job reports by posting a message into the session that started it (`client.session.promptAsync`). The model ends its turn and is woken by `<task>`, `<monitor>`, `<wakeup>`, `<cron>`, `<bg_shell>` or `<workflow>`. This needs a live opencode process, so use the server (`oc`, `coder`). A plain `opencode run` exits after its turn; the server then adopts its jobs, but a subagent it started ends with it.
- State lives in `$PARITY_STATE_DIR`, else `~/.local/state/opencode/parity/`: `jobs.json`, `primary.json`, `shells/<id>.log`, `workflows/<run>/{script.js,journal.jsonl,log.txt,result.json}`, `guard/<session>.json`, `bash_env` and `parity.log`.
- Every opencode process that loads the plugin shares `jobs.json`, under a lock. Each job names its owner process, and only the owner arms it. Other processes list it, and delete it from the file; the owner cancels it on its next sync (10 s). When an owner dies, the server (`opencode serve`, or `PARITY_PRIMARY=1`) adopts its jobs; with no server up a TUI does. `opencode run` and other subcommands never adopt.
- An adopted job resumes. Overdue wakeups fire with `late_by`. Monitors are restarted. Background shells are detached, so their exit code file is still seen. Agents report what their child left. Interrupted workflows are announced with their `resume_run_id`.
- A workflow `agent()` with a `schema` sends `format: json_schema` with `variant: "nothink"`, because DeepSeek rejects that tool choice while thinking. `think: true` asks for JSON in text instead and checks it. Opencode 1.19.5 fails any listing that reaches a user message carrying a schema ("Expected OutputFormatJsonSchema"), and the TUI may fail to open such a child. The plugin reads the newest messages that list; `session_read` shows them, with the prompt from the run's `journal.jsonl`.
- Built-in `task` with `background: true` (flag `OPENCODE_EXPERIMENTAL_BACKGROUND_SUBAGENTS`) is the normal background subagent. `agent_spawn` covers worktrees and other models, and stands in if the flag goes away.

### Guards

`tool.execute.before` refuses a call by throwing a one-line reason that names the right move. It covers every session, subagents included, and the commands of `bash`, `bg_shell`, `monitor` and workflow `sh()`. A guard that throws refuses the call. Commands are parsed: `;`, `&&`, `||`, `|`, newlines, quotes including `$'...'`, `$(...)`, here-documents and here-strings, `NAME=value` prefixes, `sudo`/`env` wrappers (with `-C`/`-D` directories), `xargs`, `bash -c`/`eval`/`source`, scripts piped or redirected into a shell or interpreter, `find -exec` (with `{}` as each root), git aliases (including one the same call defines), braces, `cd`/`pushd`/`popd` (with options), and commands inside code (`subprocess`, `os.system`, `child_process`, `system()`, osascript's `do shell script`). A script the call runs is read when it is ad hoc: written by the same call, under a temp directory, or outside every repository. A tracked script in a repository is not re-read, so a model that writes a script into a repository and runs it is judged only by the write.

Paths given as `~`, `~+`, `$HOME`, `$PWD`, `$(pwd)`, `$(git rev-parse --show-toplevel)`, `$(echo ...)`, variables the call assigned (and `read X <<< word`), relative to the directory or absolute are compared case-insensitively with symlinks resolved, including links the same call makes with `ln`. A loop variable, `read` from a pipe, and any other substitution are unknown. A glob is expanded on disk as the shell would. A searcher's pattern (`grep keys.env file`) is not a path. What stays unknown is refused where it matters: a command name the guard cannot resolve (any session), a file a content reader (`cat`, `grep`, `cp`, ...) cannot resolve unless every file it could reach is checked, a write target from the main checkout, a pathspec, and code piped from a command. The parse is a model of bash, not bash: an obfuscation it does not model can pass, so read-only agents run on an allowlist. The rules, first refusal wins:

| Rule | Refuses |
| --- | --- |
| Credentials | Reading, copying, uploading or changing `~/.local/share/opencode/auth.json`, `*.env`, `rclone.conf`, `~/.config/{rclone,media-syncer,api-keys}`, `backup-private/`, SSH private keys and plists whose keys name a key, token or secret. A recursive reader (`grep -r`, `rg`, `tar c`, `rsync`) has every file below its paths walked, narrowed by `--include`/`-g`, and is refused past 20,000 entries. Words from `$(find ...)`, `$(ls ...)` or a lister piped into `xargs` are checked by walking the lister's roots. `launchctl print`/`list` of a job whose plist holds keys, `launchctl export`, and `ps` showing environments (`ps eww`, `-E`). Names-only commands (`ls`, `test`, `stat`, `echo`, `git status`/`check-ignore`/`ls-files`) pass |
| Command name | A command name that is a variable or substitution the guard cannot resolve (`$CMD`, `$(cat f)`), in any session |
| Read-only | For `@reviewer`, `@verifier`, `@structured`, `@explore` and workflow `agent(prompt, {readonly: true})`: edit, worktree and agent-starting tools; any write outside `/tmp` (redirection, `tee`, `cp`, `mv`, `rm`, `sed -i` and sed's `w`/`e`, `uniq a b`, git `--output`, `format-patch`, `archive -o`, `bundle create`); and any program off an allowlist of read commands. Allowed: readers and searchers, git's read subcommands without `-c`, `--output`, `--ext-diff` or a pager, `sqlite3` reads without dot-commands, `curl` without a body, upload or `-o`, `make -n`, formatters in check mode, `python3 -m unittest`/`pytest`/a file under `test/`, `node --test`, syntax checks, and inline `-c`/`-e` code that neither writes, runs a program, nor hides a call (`eval`, `getattr`, `__import__`, string-built names). Tests from `/tmp`, scripts, `ln`, `osascript`, editors and variables such as `GIT_PAGER` or `NODE_OPTIONS` are refused |
| Worktrees | Any write under `~/Developer/Atlas/board/`, from any session: named targets with globs expanded and links followed, `git checkout -f/--discard-changes/restore/stash/reset --hard/clean/rm/mv/apply/am/cherry-pick/revert/rebase/read-tree -u/checkout-index` and branch switches in the main checkout, and `patch`, archive extraction, `find -delete`, `make`, formatters and code whose reach covers `board/`. Code that writes from a directory covering `board/` passes only when its literals name paths outside it and none is computed. From the main checkout a write target the guard cannot resolve is refused. `git merge`, `git pull` and `git checkout main` there pass: that is how main changes |
| Staging | `git add -A`/`--all` (and its abbreviations)/`-u` without paths, a pathspec naming the whole repo (`.`, `*`, `**`, `:/`, exclusions only, a pattern with no literal name, the root's own path), one the guard cannot resolve, `--pathspec-from-file`, `xargs git add` from a pipe, `git commit -a` or `git commit .`, in any repo |
| Self-prompt | Posting into a session through the server's session API from the shell (any host on port 4096, any HTTP client or code), or `opencode run --session` |
| Commit gate | `git commit`, `merge`, `pull`, `cherry-pick`, `am`, `revert`, `rebase`, `push`, a fetch into a local branch, `branch -f`, `checkout -B`, `update-ref`, `commit-tree`, `reset` to another commit (aliases, code and ad hoc scripts that run them included), `save-and-push.sh`, `ship.sh`, `gh pr merge`, a merging `gh api` call and `opencode run`, while the newest verify verdicts of the session or an ancestor include `fail` and none has passed since. An owner sentence saying "ship over it" lifts it, unless it is a question or a negation; text the plugin sent never does |
| Read budget | In a session started by `/ultracode`, a sixth read-type call (`read`, `grep`, `glob`, `bash`, `bg_shell`, `monitor`, `bg_output`, `session_read`, ...) before a `todowrite` of two steps or more. Its subagents are not counted |

Verdicts are recorded per round by `verify_until_pass`, else from any `verdict` fields in a workflow's result (a top-level `verdicts` array first). `result.json` and the `<workflow verdict="...">` message carry them. A failed one is quoted by its area, reason and defects (`area`, `reason`/`summary`, `defects[].what` and the like), never by the tail of its JSON.

The config hook sets `shell` to `/bin/bash` unless the config names one (`PARITY_BASH=0` skips it), and `shell.env` points `BASH_ENV` at `bash_env`, which turns pipefail on in the tool's shell and unsets itself so scripts it runs are untouched. Under a zsh shell the bash tool's description says so instead.

OpenCode 1.19.5 loads `~/.config/opencode/AGENTS.md`, then the first of `AGENTS.md`, `CLAUDE.md`, `CONTEXT.md` found walking up from the session directory to the worktree root. `OPENCODE_DISABLE_CLAUDE_CODE` (set in `env`) drops `CLAUDE.md` from that list, so when a project has a `CLAUDE.md` and no `AGENTS.md`, the system transform appends the nearest `CLAUDE.md`.
