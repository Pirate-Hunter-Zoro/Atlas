# Religion sensitivity results, tracked

The numeric artifacts behind `../religion_sensitivity.md`, copied here because
this is the only place they are under version control. `TRD-EHR/results/` is
gitignored in its own repository, and the `results` symlink at the root of this
one is gitignored here too, so a commit in either repo otherwise carries the
prose and none of the numbers.

Everything here is a copy. The analysis originals live at
`TRD-EHR/results/review/religion/`, mirrored from
`ARTIFACTS_DIR/review/religion/`, and are regenerated by
`python -m scripts.pipeline.review.religion.summarize`. If a number here
disagrees with one there, there is right and these are stale.

| File | Origin | What it holds |
| --- | --- | --- |
| `religion_summary.csv` | `review/religion/religion_summary.csv` | all six contrasts, both AUCs, the paired delta, the interval and the verdict |
| `religion_summary.json` | `review/religion/religion_summary.json` | the same as records |
| `feature_arm_deltas.csv` | `review/religion/feature_arm_deltas.csv` | the 58-column feature arm against the published feature arm |
| `embedded_arm_deltas.csv` | `review/religion/embedded_arm_deltas.csv` | the religion-free narrative arm against both the parity control and the published embedded arm |
| `feature_no_religion_metrics.json` | `review/religion/feature_no_religion/metrics.json` | that arm's full metric block and selected hyperparameters |
| `narrative_no_religion_metrics.json` | `review/religion/narrative_no_religion/metrics.json` | the same for the embedded arm |

## The three baselines, tracked here too

The report quotes comparator ROC AUCs, calibration slopes and hyperparameters
that this analysis did not produce. They are copied here so a quoted number can
be checked without a second repository.

| File | Origin | Why it is needed |
| --- | --- | --- |
| `narrative_control_metrics.json` | `review/parity/narrative_control/metrics.json` | the deciding comparator: the parity round's re-render with no content change |
| `published_feature_metrics.json` | `<encoder>/classical_ml_results_FEATURE.json` | the published feature arm's metric block |
| `published_embedded_metrics.json` | `<encoder>/classical_ml_results_EMBEDDED.json` | the published embedded arm's metric block |
| `published_feature_grid_search.json` | `<encoder>/grid_search_ml_results_FEATURE.json` | the published feature hyperparameters, which the metric blocks do not carry |
| `published_embedded_grid_search.json` | `<encoder>/grid_search_ml_results_EMBEDDED.json` | the published embedded hyperparameters, same reason |

`<encoder>` is `results/Qwen-Qwen3-Embedding-8B/google_medgemma-27b-text-it/`,
the primary encoder and judge pairing. The control-arm file is also tracked in
`../parity_results/narrative_control_metrics.json`; it is duplicated here so
this folder stands alone.

## What is deliberately not here

Per-patient held-out probabilities (`test_predictions.parquet`, ~200 KB per
arm), the 42,579 religion-free narratives, the embedding database, and the
trained model objects. Those stay under `ARTIFACTS_DIR` and its mirror. What is
tracked is what a reader of the reserve document would need to check a quoted
number, not what a re-analysis would need to recompute one.
